Stumps Ahead

A T20-style cricket game for your phone's browser. Pick a nation and your XI, then bat and bowl a full match against the computer. I built it by running a team of Claude Code agents the way I'd run an engineering team: a spec, clear owners, review gates and releases.

The goal

A quick cricket match on a phone: inspired by the big cricket video games, but much simpler. One player against the computer, touch controls, and nothing to install or sign up for. The first spec set a hard deadline (a playable build by 9am the next morning) and said to cut scope rather than slip.

It was built by a team of AI agents directed like an engineering team: each with an owner's role, contracts between their work, and a human deciding what ships.

How the orchestration works

The spec is the contract

The spec defines the data shapes and functions between the engine and the UI, and who owns which file. That let two developer agents build in parallel on separate branches without stepping on each other. Changing the contract takes a spec pull request.

"Done when" before anything ships

Release specs list the checks QA and security must pass. A standing list of release blockers covers the classic bugs in quickly built games: score maths, timers that double-fire, double taps and leftover state.

A human decides what ships

Nothing reaches main without my approval. I pick each release from the researcher's backlog, and when several pull requests depend on each other, the merge order is planned up front.

Cut scope, don't slip

The first spec carried an ordered cut list (difficulty levels, animation, the 10-over option) so the deadline held even if something turned out harder than expected.

A testable engine

All randomness goes through one seeded generator, and the match engine never touches the page. That makes every rule testable in Node with repeatable results.

Secure and original by default

A strict Content Security Policy, no third-party scripts and safe text rendering. Player names are made up every session and checked against a list of real cricketers, and real grounds appear by their plain names only.

Architecture

Plain HTML, CSS and JavaScript modules: no framework and no runtime dependencies. There's no backend or account, and nothing is stored. Vercel serves a minified build with security headers.
